## Implemented

The native dialog progresses through **Import your data → Integrating your data… → Your data is ready → Open dataset**. Choosing or dropping starts the existing worker-based ETL immediately. Eligible authorized saved mappings finalize automatically. The initial surface has the drop zone, Choose file, supported formats and a smaller folder action. Source fields, mappings and QC tabs are optional Advanced controls.

Real Extracting, Validating, Saving and Integrating stages use an indeterminate indicator. Ready follows admission, immutable batch creation and read-back through the actual workspace catalogue and dataset detail API. Open dataset selects that batch in Data Workspace. Partial results show imported/quarantined counts; rejected rows and reasons remain available. Invalid data is quarantined without an admitted snapshot. Missing source facts are requested individually; unprofiled or drifted data never silently inherits an unrelated last profile. Folder files retain their own authorized source context. Checksum-verified pending originals survive missing-information recovery. Advanced expansion is clamped to the available screen.

A repeat-import defect found during native restart testing is fixed in import adapter **0.1.1**: JSON preset key ordering can no longer create a different batch for identical canonical data. New writes use the existing identifier-first canonical column order. Legacy byte identities are retained only after checking the stored artifact hash and equality of every canonical value for the same original checksum, source and family. QC and rights still run through the existing admission gate. Existing immutable batches are not rewritten. No scientific estimator, optimizer, qualification criterion, database architecture or ETL framework was changed. Pending original copies are retained; automatic pruning was not added.

# RES-636 qualification — vendor-neutral scientific data workspace and one-click import

Engineering record, not product acceptance (RES-613 remains the owner gate). Scope is vendor-agnostic: no vendor-specific adapters. Source commit of the packaged application: `8d7f2589596b8c05b88e88178af881337c054e5e` (branch `codex/res-621-research-workflow`, local, unpushed).

## What exists (VERIFIED unless marked)

**Canonical data model.** Two grains over the existing SQLite + Parquet storage, no new database:
- Trial-level (`CMJ_FORCE_PLATFORM`, `SPRINT_TIMING`): Subject → Session → Trial → Measurement (canonical column, canonical unit). Table `cmj_trials` / `sprint_trials`.
- Sample-level (`RAW_FORCE_TIME`, `dynamis_science/traces.py`): Subject → Session → Trial → Trace → sample (`time_s`, optional `sample_index`) → channel (`force_z_n`, `force_left_n`, `force_right_n`, `force_combined_n`, newtons). Tables `force_signals` (samples) and `trace_index` (one row per trace: sample count, time origin, duration, declared and implied sampling rate and its source, channels, instrument, protocol). A trial id repeats across samples; the unique key is subject/session/trial/time. A trial id shared by two subjects or sessions is rejected, never merged.
- Raw versus derived: no derived metric is computed by import; vendor-computed and locally derived values are not mixed (no vendor adapter exists).

**Import (`importer.py`, `desktop/import_review.py`).** Formats: CSV/TSV/TXT (UTF-8/BOM; comma, semicolon, tab, pipe), Parquet, Arrow/Feather, Excel (.xlsx/.xlsm: cached values of the first sheet with data, other sheets disclosed; converted once to a Parquet cache under the data root), JSON (array of records) and NDJSON. Google Sheets has no connector (no cloud): download as .xlsx or .csv and import the file; single files and bounded non-recursive folders (≤100 files, symlinks skipped). Pipeline: detect → propose mapping with confidence and ambiguity → deterministic unit conversion → per-row QC → existing admission QC → immutable snapshot (batch). Units: kg/g/lb, cm/m/mm/in, s/ms, N/kN/lbf, Hz, N·s/kg, W/kg; an unstated or unsupported unit is a question, never a guess.
- **Per-row QC flags:** rows with a missing identifier, a duplicated trial id or an implausible value are quarantined individually with a reason (`quarantine/<receipt>/rows.parquet`); clean rows continue to the unchanged admission QC. Sample-level files are judged per file (see limits).
- **Source profile and presets:** after the first admission the mapping and source/instrument/protocol context are remembered (identity values such as session/subject/trial are not). The same schema is then one click; any header or type change is drift and is reviewed. A file with no session column is one session named after the file, stated in the summary.
- **Logical dataset per source profile:** the union of that source's immutable batches (each row tagged `batch_id`), shown in the Data workspace; a new file adds a batch, earlier batches are never touched; analysis binds to one batch.
- **Never invented:** calibration, rights, units, sampling rate (estimated from timestamps only when absent, labelled `estimated_from_timestamps` with a warning), force orientation/zeroing (warning when unspecified). TEST_FIXTURE stays `SYNTHETIC_ONLY`; real data needs verified rights and a CALIBRATED instrument or is quarantined (tested for trace data too).

**Streaming and limits.** Probe reads the first 64 KiB plus a streaming row count; sample-level normalization is `scan → sink_parquet`; QC iterates Parquet batches of 500,000 rows holding O(traces) state; snapshot is a streamed copy. Limits: 4 GiB file, 100,000,000 samples per recording (explicit rejections); trial-level tables are read whole and capped at 256 MiB.

**Data workspace (`desktop/data_workspace.py`, Research → Data workspace, Ctrl+D).** Catalogue of logical datasets, batches and existing datasets with search; paged (200 rows) table with sorting, column chooser and filters (contains, comparisons, empty); column profile (type, unit from canonical name, missingness, range); Traces tab using the existing signals view (first recording plotted); read-only SQL (Polars SQL; only SELECT; writes, files, paths, comments and multiple statements are refused; 10,000-row cap); Quality and lineage (rights, QC verdict, exclusions, instrument, import receipt with raw SHA-256, content hashes, parser version, studies); "Analyze this dataset" opens the selected batch in the research workbench. **Saved queries:** a SELECT can be saved by name (same gate as running; same name adds a version, earlier ones kept) and reused from a picker; stored in `artifacts/saved_queries.json`. **Compare tab:** for a raw force-time recording, values derived now from the raw samples (peak, mean, trapezoidal impulse, duration; method DS-DERIVE-1.0; not stored, not a vendor value) are shown beside recorded values read from trial-level tables of the same source with the same subject and trial id, with the origin of each. **Screen layout:** single-line catalogue with batches indented, tabs Data / Columns / Traces / Compare / Query / Provenance, filters shown only when set; the import details are three tabs (Source with the essentials first and "More" for the rest, Data and mapping, QC report), the rights review appears only for non-fixture data, and the QC result is re-run if the source form changes after QC.

## Not verified / limits

- **Vendor-agnostic by design.** There are no vendor adapters, SDKs or vendor-specific formats; any CSV/Parquet export that carries the needed columns imports through the generic mapping. No compatibility with any particular manufacturer is claimed or required.
- The frozen run covers the keyboard journey above; the installer was not run. The import window opens tall even with details closed (cosmetic, left as is). Only 100% display scaling was tried on the frozen build; 150% was tested on the source application only. Other DPI/hardware not tested.
- Sample-level QC is per file (a file with any rejected trace is not admitted); per-row flags apply to trial-level tables only. Duplicate sample times are rejected, not repaired.
- Trace snapshots are browsed, queried and plotted; scalar analyses cannot run on them (no derived metrics are computed); the qualified methods bind to `signal_trials`/`cmj_*` tables and are untouched.
- A logical dataset is browse/query/inspect only; analysis opens one batch. Combining batches into one analysis snapshot is not built.
- Trial identifiers must be unique per file (export numbering per athlete needs a composite id). C3D and other binary formats are not supported; Excel reads cached values only (no formulas, one sheet). Read-only SQL is a keyword filter over Polars SQL, not a sandbox proof. Query/page calls have row caps but no wall-clock timeout.
- Cancel is not offered during import. Windows only.
- Earlier packaged-app screenshots (`frozen-01/02`) showed a user desktop and were removed from the tree; they remain in commit `b023d41` history (not rewritten).
