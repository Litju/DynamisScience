## 1. What was added

The accepted RES-116/RES-587 Research / Data / Library navigation and
Study Tree → Scientific Workbench → Contextual Inspector geometry is unchanged.
The existing typed-block investigation model, viewers, evidence promotion,
lineage and report surfaces are reused.

New persistent research objects:

- **Research projects** with generated IDs, objectives, associated admitted
  datasets, version history, archive/restore and no destructive cascade.
- **Scientist-authored studies** with question, hypotheses, design, population,
  outcomes, protocols, schedule, cohort binding, analysis plan and validated
  states `DRAFT → READY → ACTIVE/ANALYSIS → COMPLETED → ARCHIVED`.
- **Monitoring programs** with population, metric, protocol, prospective
  schedule, quality/missingness policy, longitudinal analysis settings and a
  persisted investigation. Planned measurements are stored separately from
  recorded readings.
- **Declarative, snapshot-bound cohorts** with inclusion/exclusion rules,
  minimum observations, activity filters, resolved included/excluded subjects,
  reasons, missingness and fork-on-change semantics.
- **Draft / frozen / forked AnalysisPlans** with content hashes, frozen
  timestamps, content-addressed specifications, estimand, effects, time coding,
  contrasts, missing-data policy and diagnostics. Frozen plans are immutable.
- **Immutable AnalysisRuns, EvidenceArtifacts and FigureArtifacts** for
  user-authored studies, with optimizer/estimator, warnings, diagnostics,
  result digests and reproducibility keys.
- **Versioned reports** with explicit freeze, historical versions, citation
  tables and a working downloadable standalone HTML export with an embedded
  machine-readable manifest.
- **Named investigations** per study/program with create, fork, save/reopen,
  dependency-safe reorder, collapse and the existing typed block model.
- **Method eligibility** before execution, including qualified / descriptive /
  rejected status and explicit rejection of unsupported combinations.

### Persistence design

`researchstore.py` adds a small transactional SQLite store with WAL, foreign-key
checks and schema versioning. It contains projects, entity versions, cohorts,
plans, investigations, runs, evidence, figures, report versions, citations and
audit rows. Raw admitted Parquet snapshots and their checksums remain read-only
and are never copied into this database or regenerated by it.

- Optimistic concurrency: every mutable object carries `version`; stale updates
  return HTTP 409.
- Frozen plans, cohorts, runs, evidence and report versions are append-only.
- Archiving changes status only; no scientific child is deleted.
- `pnpm data:generate` writes the synthetic fixture and cannot reset the
  research database. This is exercised by a regression test.

**Computed result.** MixedLM `cmj_height_cm ~ occasion_c + (1 + occasion_c |
subject_id)`, ML, 82 observations from 21 athletes. Slope **+0.998 cm per
occasion** (SE 0.192; 95% CI 0.622 to 1.375); model-implied change occasion 1 →
4 **+2.995 cm** (95% CI 1.866 to 4.124); log likelihood **−208.3118**. The
selected estimator was `MIXEDLM_RANDOM_SLOPE` after evaluating L-BFGS-B, BFGS,
Powell and Nelder–Mead. This matches the RES-587 R/lme4 qualification.

The study is single-arm and observational. The interface and report state that
this is a within-athlete change, not a causal intervention effect. Occasions are
not relabelled as calendar weeks.

## 8. Limitations

- The plans are frozen locally, not prospectively registered with an external
  registry. The UI and reports say so explicitly.
- Mendeley contains derived scalars only; there are no raw force traces. The
  four occasions are not mapped to calendar weeks.
- The Mendeley design is single-arm; no control arm or causal intervention
  effect is inferred.
- MoveSmart is a repeated-trial measurement dataset, not a longitudinal season.
  There is no CMJ task and no validated sample-level IMU/GRF synchronisation.
- The monitoring program has no new readings. Its schedule is prospective and
  its available readings are historical; they are not relabelled.
- The local research store is single-user and has no authentication or
  multi-tenancy. It uses optimistic concurrency and transactional writes but does
  not attempt multi-process collaborative editing.
- HTML report figures are deterministic inline SVG generated from stored
  aggregate figure artifacts. No external scripts, fonts or network assets are
  required.
- RES-587's external practitioner validation remains a human gate and cannot be
  satisfied by code or automation.
